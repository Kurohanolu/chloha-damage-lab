# v0.177 Pre-Release 16 — Phase 1 計算エンジン監査

## 対象と判定
基準: main v0.176。既存の `tests/damage-regression.cjs`、`tests/v0171-runtime.cjs`、`tests/conditional-power-ui.cjs` を維持する。
自動テストの成功は「実装内の整合性」を示すものであり、Pokémon Champions実機との一致は未確認。

## コード監査で確認した実装
- `calculate(a)` が攻撃・防御の能力ランク、威力補正、基礎ダメージ、乱数85〜100、最終補正を順次計算。
- 通常技は16個のダメージ乱数を返す。ダブルウイングは16×16=256組を返す。
- 条件付き威力は `effectivePower` にまとめて適用。はたきおとすは65→97（整数切り捨て）、からげんきは70→140。
- 急所時は攻撃側の負の能力ランクと防御側の正の能力ランクを無視する。
- 特殊な相性・複数ヒットなどは、未対応時に計算を止める安全策を維持する。

## Phase 1で必須の追加テスト
1. 乱数16段階、非負整数、最小値・最大値の単調性。
2. 攻撃ランク-1 / 防御ランク+1を急所が無視すること。
3. タイプ無効で全乱数0、通常の有効打で正の整数になること。
4. 条件付き威力のON/OFFで `effectivePower` が規定値となること。
5. 天候・フィールド・壁・やけど・ダブル補正の各単独／複合テスト。
6. 不正入力・未対応技は古い計算結果を表示しないこと。
7. 既存UI回帰テストを360/390/1280pxで通すこと。

## リスクと保留
- `DamageEngine.version` が0.162のままで、画面表示のv0.176と異なる。エンジン内部版と製品版の区別を明示するか統一する。
- 技DBの `calculationSupported` と実行時の `ChlohaMovePolicy.standardDamageSupported` の二系統がある。Phase 3で単一の表示判定に統合する。
- `conditionalPower` は手動指定で、状態異常などの条件を自動判定しない。Phase 2で入力との連携範囲を定義する。
- 係数の丸め順序と補正の重複は、独立した期待値を使って検証する。既存実装から期待値をコピーするだけのテストは合格根拠にしない。
- 実機照合が未完了のため、v0.177の完成時も「実機未照合」を維持する。
